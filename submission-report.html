What the assignment asked

Build a production-minded Python API that cleans retail CSVs and answers grounded questions. The code must validate, execute and verify each proposed plan. The brief gives four calendar days, estimates 12–18 focused hours and permits AI tools.

Data quality · p. 2
Persist runs and original/cleaned CSVs. Profile schema, shape, nulls, duplicates, cardinality, parse failures and distributions before and after. Plan changes with stable IDs, reasons, affected fields, risk, source and status. Validate row/schema deltas, unresolved issues and rerun stability.
Retail intelligence · p. 2
Choose at least two of normalization, safe relationships, auditable scoring/recommendations, and analytics. This submission implements safe joins and sales analytics.
Chat · p. 3
Support filters, sorting, grouping, aggregates, comparisons, rankings, distinct values and statistics. Persist follow-ups, validate joins and return versioned evidence. Handle ambiguity, missing data, injection, invalid plans, model failure and raw/cleaned conflicts.
Evaluation · p. 4

What we built and why

One FastAPI application and one shared Python service. DuckDB handles data work. SQLite holds the run and conversation metadata. Ordinary files hold the downloadable evidence.

  1. IngestValidate CSVs and hash original bytes.
  2. CleanProfile, plan, apply and reconcile.
  3. QueryValidate intent, scope and join.
  4. ProveExecute and persist the evidence.
Preserve before changing
Stage fields as text to keep SKU 001 intact. Normalize agreed formats and leave the ambiguous date 03/04/2025 unresolved. Retain duplicate rows and flag conflicts. Verify row and schema deltas before publication.
Guard the math
Require a unique catalog SKU before joining, then reconcile fact row counts and count missing keys. Calculate gross sales, average order value and unit return rate with documented eligibility. Show components and coverage.
Use the model for planning
Nemotron proposes a typed plan. The server owns workspace access, data version, legal joins, filters, limits and the calculation. Explicit region commands update scope locally. Hosted planning gets the question and schema metadata. CSV cells stay local.
Share the executable path
The browser and reviewer CLI call the same service. For evaluation the planner is deterministic or receives an injected test plan. The executor, cleaning ledger and evidence formatter stay shared.

Single-node operation, one supported join, and a limited offline grammar keep the implementation small. The app documents limits on file size, rows, query time, and concurrency. Broader retail relationships, fuzzy category merging and production identity are outside this submission’s chosen scope.
